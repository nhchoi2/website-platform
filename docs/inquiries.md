# 온라인 제작 상담

## 구현 범위

- `/contact`: 회원가입 없는 상담 접수, 선택한 디자인·업종·페이지·기본/유료 옵션·메뉴 배치·가격 요약.
- `/api/inquiries`: 동일 출처 POST와 서버 입력 검증. 연락처는 비공개 DB에 저장. 성공한 접수 번호만 반환하며 공개 조회 API 없음.
- `/admin/inquiries`: 기존 운영자 권한 확인 후 최근 200건 조회, 검색·상태 필터, 상태·비공개 메모 저장, 목적 달성/철회 시 상담 정보 삭제.
- 고객·익명은 직접 테이블 조회·수정·RPC 접수 불가. 서버 전용 service-role은 좁은 접수 함수에만 사용. 기존 고객 데이터 처리 경로는 변경하지 않음.
- 같은 요청 키/내용의 재시도는 같은 접수 번호. 키에 다른 내용을 붙이면 거절. 동일 연락처 시간당 3건, 전체 하루 100건 제한을 DB 트랜잭션으로 검사. Honeypot과 필드 길이 제한도 적용. 연락처 해시는 서버 키로 HMAC 처리. CAPTCHA/분산 봇 방어 서비스는 아직 없음.
- 메일 알림 대기열을 실제 접수와 함께 저장한다. Resend 설정·활성화 후 운영자 알림과 고객 이메일 접수 확인을 발송한다. 문자 발송은 사용자가 추후 연결하기로 했다.
- 메모는 운영자용이며 고객에게 공개하지 않는다. 연결된 고객의 상담 이력·제작 진행·자료 업로드는 [제작 관리 연결](managed-workflow.md)에 구현했다. 추천 설문·찜하기는 이번 구현 범위 밖이다.

## 로컬 검증

APP_MODE=local이면 기존 PGlite에 `005_inquiries.sql`을 적용한다. 화면에 로컬 시연 안내를 표시하고 실제 고객 연락처를 사용하지 않는다. 새로고침/DB 재시작 후에도 저장되며 테스트는 격리 임시 DB 사용.

## 운영 연결

1. Supabase SQL Editor에 `supabase/migrations/005_inquiries.sql`을 한 번 적용한다(2026-10-03 운영 적용·익명 권한 차단 확인 완료). 006~009도 사용자 승인 후 2026-10-03 운영 적용·익명 접근 차단을 확인했다. 기존 migration은 재실행하지 않는다.
2. Vercel 서버 환경에 기존 `SUPABASE_SERVICE_ROLE_KEY`가 있는지 확인한다. 키를 채팅·Git·브라우저 번들에 노출하지 않는다.
3. 상담 수집·이용 안내(consultation-2026-10-03), 처리 주체·위탁/국외이전 및 보유/파기 절차를 확인한다. 이번 상담 동의는 회원 계정 동의와 별개다.
4. 준비 완료 후 Vercel 환경 변수 `INQUIRIES_ENABLED=true`를 설정하고 배포한다. 그 전에는 접수 폼을 비활성화하고 이메일 문의를 안내한다. 로컬 성공을 Supabase 운영 연결 완료로 취급하지 않는다.
5. 운영 계정으로 상담 저장→목록 확인→상태 변경을 실제 연결 DB에서 재검증한다. 사용자로 `/admin/inquiries`와 API 접근이 거절되는지 확인한다.

## 개인정보와 유지보수

- 이름/연락처/내용을 로그로 남기지 않는다. 고객 상담 화면 응답에 다른 사람의 정보나 접수 목록을 넣지 않는다.
- 상담 목적이 달성되거나 삭제 요청을 받으면 운영자가 관리자 화면에서 삭제한다. ‘종료’는 처리 상태이며 자동 삭제가 아니다. 법령상 별도 보관 필요성과 계약 이관은 실제 업무에 맞게 검토한다.
- 백업에도 개인정보가 남을 수 있다. DB 백업·복구 절차와 공급자의 백업 보관 기간을 확인하고 삭제 요청 처리에 반영한다. 재해 복구 시 이미 삭제한 정보가 다시 사용되지 않게 점검한다.
- 요청량 제한은 키 교체 시 기존 HMAC 연락처 버킷이 바뀐다. 봇 공격 시 별도 WAF/CAPTCHA를 검토한다. IP 주소는 별도로 저장하지 않는다.
- 목록은 최근 200건 제한. 운영 규모가 커지면 서버 페이지네이션과 알림을 추가한다.

수정 위치: `lib/inquiries.ts` 입력/구성 요약, `components/inquiries/` 화면, `lib/server/inquiries.ts` 접수 저장, `005_inquiries.sql` RLS/RPC. SQL 변경은 다음 번호 migration으로 기록한다.
